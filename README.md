# BC Forest Sector Climate Benefits Modeling Framework

This repository contains the mathematical modeling framework developed to simulate and optimize the climate change mitigation potential of the British Columbia (BC) forest sector, encompassing both the forest ecosystem and the harvested wood products (HWP) industry.

---

## Overview

The framework integrates [libcbm_py](https://github.com/cat-cfs/libcbm_py) with [ws3](https://github.com/UBC-FRESH/ws3) to:

1. Generate, plug in, and validate the carbon yield curve method at stand and landscape levels.
2. Compare and optimize harvest and HWP scenarios to maximize total carbon stock and minimize net carbon emissions from the forest system.
3. Perform sensitivity analyses on the impact of key HWP climate parameters on optimal forest carbon management plans.

All analyses are implemented in Jupyter notebooks for reproducibility and extension.

## Getting started

### 1. Clone with submodules

```bash
git clone --recurse-submodules https://github.com/UBC-FRESH/msc_walter_yan.git
# or, if already cloned:
git submodule update --init
```

### 2. Environment

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install ./ws3 ./libcbm_py   # pinned submodule versions (recommended)
# or, from PyPI: pip install ws3==1.0.5 libcbm==2.10.2
```

### 3. Run

- `generate_c_curves_single_stand.ipynb`, `generate_c_curves_tsa24.ipynb` — carbon yield curve
  generation, plug-in, and validation against libCBM.
- `python run_no_harvest_comparison.py` — regenerates the no-harvest comparison artifacts in
  `outputs/no_harvest/`.
- `minimize_emission_loop.ipynb` — runs the half-life / displacement-factor scenario loop
  (writes to `results/`, which is git-ignored; published separately).
- `sensitivity_analysis.ipynb` — produces the sensitivity figures from the loop outputs.

## Conventions and gotchas

- **Time units.** ws3 measures stand age and action timing in years. This project's
  Woodstock-format files use ages in years (5..475), so no conversion is needed. For
  Woodstock files that define time in periods, pass
  `convert_periods_to_years=<period_length>` to `import_areas_section`,
  `import_yields_section`, `import_actions_section`, and `import_transitions_section`.
- **Inventory reporting.** `ForestModel.inventory(period, ...)` reports the inventory at the
  *end* of the period (aged by `period_length`), matching Woodstock's period outputs
  (ws3 >= 1.0.5; verified by the Woodstock parity tests in UBC-FRESH/ws3).
- **Harvest flag.** Set `fm.actions['harvest'].is_harvest = True` after importing a model
  from Woodstock files. Without it, `cmp_c_z`-based objectives compile to zero coefficients.
- **Solvers.** ws3 supports HiGHS (open source; default in ws3 >= 1.0.5) and Gurobi. The
  notebooks currently call Gurobi; for the base (max even-flow harvest) scenario, both
  solvers agree to ~1e-7.
- **Outputs.** `outputs/no_harvest/` is regenerated by `run_no_harvest_comparison.py`;
  `results/` (scenario-loop outputs) is git-ignored.
